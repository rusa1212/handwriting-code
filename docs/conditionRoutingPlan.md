# 상황 반영 경로 탐색 작업 계획

> 목표: 알고리즘 실험실의 도로망 그래프(`algorithmLabPlan.md`) 위에서 **공연·기상 정보로 막히거나 느려지는 길을 피해** 경로를 찾는다.
> 같은 출발/도착에 대해 **평소 경로 vs 회피 경로**를 지도에 함께 보여 주고 시간 차이를 비교한다. (`mapping.md` LEVEL 5)

---

## 진행 현황

| 단계 | 내용 | 구분 | 상태 |
|---|---|---|---|
| 1 | 거리 가중치 → 시간 가중치 전환 + A\* 휴리스틱을 시간 단위로 변경 + 기존 검증 재실행 | 필수 | ⬜ |
| 2 | 상황 모델 (`Event`, `Weather`, `Closure`) + 시나리오 JSON (`be/conditions.py`) | 필수 | ⬜ |
| 3 | 공연 배수: 공연장 반경 + 시간 창 | 필수 | ⬜ |
| 4 | 기상 배수: 강수·적설 감속, 취약 도로 추가 배수, 폭우 시 통제 | 필수 | ⬜ |
| 5 | 백엔드 API 확장 (`departure_time`, `scenario` → `normal_path`, `penalized_edges`) | 필수 | ⬜ |
| 6 | 실험실 화면: 공연장 원, 영향 도로 색칠, 평소/회피 경로 비교 | 필수 | ⬜ |
| 7 | 실제 데이터 연결 (기상청 초단기실황, KOPIS 공연) | 선택 | ⬜ |

1~6단계는 **직접 만든 시나리오 JSON**으로 끝낸다. 외부 API가 "오늘 맑음, 공연 없음"을 돌려주면 회피 효과를 시연할 수 없기 때문이다.
7단계에서 같은 모델(`Event`, `Weather`)을 실제 API 응답으로 채우기만 하면 된다.
(`algorithmLabPlan.md`에서 "작은 그래프로 먼저 검증한 뒤 웹에 붙인다"와 같은 방식)

## 정한 것

| 질문 | 결정 | 이유 |
|---|---|---|
| 어느 탭에 붙이나 | **알고리즘 실험실 탭** | 카카오 길찾기는 완성된 경로만 줘서 회피 탐색을 할 수 없다 (점수 매기기만 가능). 직접 만든 그래프가 있는 실험실에서만 경로 자체를 바꿀 수 있다 |
| "막힘"의 의미 | **느려짐(배수) + 통제(간선 제외)** 둘 다 | 배수만 있으면 경로가 조금만 바뀐다. 통제가 있어야 확실히 돌아가는 모습이 보인다 |
| 시간 의존성 | **출발 시각 하나로 상황 고정** | 2km 영역이라 이동이 몇 분이다. 이동 중 시각에 따라 가중치가 바뀌는 탐색(time-dependent Dijkstra)은 하지 않는다 |
| 데이터 | **시나리오 JSON 먼저**, 실제 API는 7단계 | 위 "진행 현황" 참고 |

## 핵심 아이디어

```text
간선 비용(s) = 기본 시간 × 공연 배수 × 기상 배수     (배수는 항상 ≥ 1)
통제 구간    = 간선 제외 (비용 ∞)
```

- 탐색 함수(`dijkstra`, `astar`)의 구조는 그대로 둔다. **간선 가중치를 어디서 가져오는지만** 바꾼다.
- 상황을 반영하지 않은 그래프(`base`)는 서버에 한 번만 만들어 두고, 요청마다 시나리오를 적용한 **가중치 함수** 또는 **가중치를 바꾼 복사본**을 쓴다. `get_graph()` 캐시를 직접 고치면 다른 요청에 상황이 새어 들어간다.

### A\* 최단 보장 유지

- 지금은 "간선 거리 ≥ 직선거리"라서 `h = 직선거리`를 써도 최단이 보장된다 (`algorithmLabPlan.md` 2-5).
- 시간 가중치에서는 `h = 직선거리 ÷ v_max`로 둔다. `v_max`는 **그래프에 남은 간선 중 가장 빠른 속도**다.
  - 어떤 간선도 `거리 ÷ v_max`보다 빨리 지날 수 없으므로 남은 시간을 부풀리지 않는다.
  - 배수가 1 이상이면 시간이 늘기만 하므로 이 조건이 계속 지켜진다. **배수가 1보다 작으면 안 된다** (예: "공연 끝난 뒤 한산함"을 1 미만으로 두지 않는다).
- 가장 큰 덩어리만 남기면 호남고속도로(`motorway`, 100km/h)가 빠지므로 `v_max`는 고정값이 아니라 그래프를 만든 뒤 계산한다. `v_max`를 실제보다 크게 잡아도 최단은 보장되지만 A\*가 다익스트라처럼 넓게 퍼진다.

## 1단계 ⬜ 시간 가중치 전환 (`graph.py`, `search.py`)

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 1-1 | 도로 종류별 기본 속도 표 + `maxspeed` 우선 사용 | ⬜ |
| 1-2 | `load_osm_graph()`에서 간선마다 거리(m)와 시간(s)을 함께 저장 | ⬜ |
| 1-3 | A\* 휴리스틱 `직선거리 ÷ v_max` | ⬜ |
| 1-4 | `_check_osm()` 재실행: A\* 비용 = 다익스트라 비용, A\* 방문 ≤ 다익스트라 방문 | ⬜ |

- 현재 데이터에서 `maxspeed`가 있는 도로는 504개 중 25개뿐이다 (100: 10, 60: 8, 30: 7). 나머지는 `highway` 기본값을 쓴다.

| `highway` | 개수 | 기본 속도 (초안) |
|---|---|---|
| `primary` | 8 | 50 km/h |
| `secondary` (+ `_link`) | 36 + 9 | 50 km/h |
| `tertiary` (+ `_link`) | 31 + 3 | 40 km/h |
| `residential` | 179 | 30 km/h |
| `living_street` | 17 | 20 km/h |
| `service` (캠퍼스 안) | 209 | 20 km/h |

- 간선에 **거리와 시간을 둘 다** 남긴다. 결과 요약에 "거리 3.0km / 예상 6분"을 같이 보여 주고, 거리 기준 탐색(LEVEL 4 결과)과도 비교할 수 있다.
- 기존 실험실 화면은 거리 기준으로 확인했으므로, 요청에 `metric: "distance" | "time"`을 두고 기본값을 정한다 (5단계).

## 2단계 ⬜ 상황 모델 (`be/conditions.py`, `be/data/scenarios.json`)

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 2-1 | `Event`, `Weather`, `Closure`, `Scenario` 자료형 | ⬜ |
| 2-2 | 시나리오 JSON 읽기 + 예시 3개 작성 | ⬜ |
| 2-3 | `edge_multiplier(edge, scenario, time)` 뼈대 (아직 전부 1) | ⬜ |

```text
Event    = { name, lat, lng, radius_m, start, end, crowd }   crowd: 1(소규모) ~ 3(대규모)
Weather  = { rain_mm_h, snow_cm, temp_c }
Closure  = { way_ids | 좌표 구간, reason }
Scenario = { id, label, events[], weather, closures[] }
```

- 예시 시나리오 (전남대 주변):
  - `concert`: 캠퍼스 안 공연장 저녁 공연 (대규모) → 정문 쪽 도로 혼잡
  - `heavy_rain`: 시간당 30mm 폭우 → 전체 감속 + 지하차도 통제
  - `concert_rain`: 둘이 겹친 경우
- 간선이 어느 도로(way)에 속하는지 알아야 통제·태그 판단을 할 수 있다 → 1-2에서 간선마다 `way_id`(또는 태그)를 함께 남긴다.

## 3단계 ⬜ 공연 배수

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 3-1 | 시간 창: 시작 1시간 전 ~ 시작(입장), 종료 ~ 종료 30분 후(퇴장)에만 적용 | ⬜ |
| 3-2 | 거리 감쇠: 공연장에서 가까울수록 큰 배수, 반경 밖은 1 | ⬜ |
| 3-3 | 공연장 바로 앞 구간 통제 옵션 (대규모 공연) | ⬜ |
| 3-4 | 터미널 확인: 공연장을 지나던 쌍이 회피 경로로 바뀌는지 | ⬜ |

```text
d = 간선 중점 ~ 공연장 거리
배수 = 1 + crowd × (1 - d / radius_m)     (d < radius_m 일 때)
```

- 간선 중점 기준으로 판단한다 (양 끝 노드 중 하나만 반경 안이어도 간선은 걸친다).
- 공연이 여러 개면 배수를 곱한다. 너무 커지지 않게 상한(예: 5배)을 둔다.
- 시간 창 밖이면 공연이 있어도 배수 1. "같은 장소, 다른 출발 시각"으로 결과가 달라지는지 확인한다.

## 4단계 ⬜ 기상 배수

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 4-1 | `fetch_osm.py`의 `KEEP_TAGS`에 `tunnel`, `bridge`, `layer`, `lanes` 추가 후 다시 받기 | ⬜ |
| 4-2 | 전체 감속: 강수량·적설량 구간별 배수 | ⬜ |
| 4-3 | 취약 도로 추가 배수: 다리(결빙), 좁은 길(`service`, `living_street`) | ⬜ |
| 4-4 | 폭우 시 지하차도(`tunnel=yes` 또는 `layer<0`) 통제 | ⬜ |

| 조건 | 전체 배수 (초안) | 추가 |
|---|---|---|
| 맑음 | 1.0 | |
| 비 (< 10mm/h) | 1.1 | |
| 비 (10~30mm/h) | 1.25 | 좁은 길 × 1.2 |
| 폭우 (≥ 30mm/h) | 1.4 | 지하차도 **통제** |
| 눈 / 기온 ≤ 0℃ | 1.5 | 다리 × 1.5 |

- 전체 감속만 있으면 모든 간선에 같은 배수가 곱해져 **경로는 그대로이고 시간만 늘어난다**. 경로가 바뀌려면 도로마다 다른 배수(4-3, 4-4)가 있어야 한다.
- 4-1에서 OSM을 다시 받으면 노드·간선 수가 `algorithmLabPlan.md` 기록과 달라질 수 있다. 다시 받은 날짜와 수를 적어 둔다.
- 영역 안에 지하차도·다리가 없으면 4-4는 시나리오에 `Closure`를 직접 넣어 시연한다.

### 통제 때문에 생기는 새 예외

- 지금 그래프는 "가장 큰 덩어리"만 남겨 경로 없음이 생기지 않는다. **통제로 간선을 빼면 덩어리가 갈라질 수 있다.**
- 출발/도착이 통제로 고립되면 `path = []`, `cost = null`. 화면에 "통제 구간 때문에 갈 수 없습니다"로 보여 준다.
- 출발/도착 노드 맞추기(`_snap`)는 통제와 관계없이 원래 그래프로 한다.

## 5단계 ⬜ 백엔드 API (`schemas.py`, `lab.py`, `main.py`)

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 5-1 | 요청에 `scenario`, `departure_time`, `metric` 추가 | ⬜ |
| 5-2 | 상황 반영 탐색 + 같은 쌍을 상황 없이 한 번 더 탐색해 `normal_path` | ⬜ |
| 5-3 | 응답에 `penalized_edges`, `events` 추가 (화면 색칠용) | ⬜ |
| 5-4 | `GET /api/scenarios`: 시나리오 목록 | ⬜ |

| 엔드포인트 | 요청 | 응답 |
|---|---|---|
| `POST /api/search` | 기존 + `{ scenario, departure_time, metric }` | 기존 + `{ normal_path, normal_cost, penalized_edges, events }` |
| `GET /api/scenarios` | | `[{ id, label }]` |

- `scenario`가 없으면 지금과 똑같이 동작한다 (기존 실험실 화면이 깨지지 않게).
- `penalized_edges`: `[[lat1, lng1, lat2, lng2, 배수 또는 null(통제)], ...]`. 배수 1인 간선은 보내지 않는다.
- `normal_cost`는 **평소 경로를 상황 반영 가중치로 다시 계산한 값**이다. "평소 길로 가면 지금 몇 분 걸리는지"가 비교 대상이다.
- 잘못된 `scenario` id는 400.

## 6단계 ⬜ 실험실 화면 (`MapView.jsx`, `AlgorithmLabPage.jsx`)

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 6-1 | 사이드바: 시나리오 선택 + 출발 시각 입력 | ⬜ |
| 6-2 | 공연장 원 (`rects`처럼 `circles` prop) | ⬜ |
| 6-3 | 영향 도로 색칠: 배수 크기별 노랑 → 빨강, 통제는 회색 점선 | ⬜ |
| 6-4 | 평소 경로(옅은 선) + 회피 경로(강조 선) 함께 그리기 | ⬜ |
| 6-5 | 결과 요약: "평소 길로 가면 9분 → 회피 경로 6분 (3분 단축, 0.4km 더 김)" | ⬜ |
| 6-6 | 시나리오별 화면 확인 | ⬜ |

- 기존 패턴대로 상태는 페이지가 갖고 `MapView`는 그리기만 한다.
- 탐색 애니메이션(`visited_order`)은 그대로 쓴다. 공연장 근처에서 탐색이 퍼지다 멈칫하는 모습이 보이면 좋다.
- `zIndex`: 영역 사각형 0 < 영향 도로 1 < 방문 점 … < 경로. 기존 순서(`algorithmLabPlan.md` 5-1)에 끼워 넣는다.

## 7단계 ⬜ 실제 데이터 연결 (선택)

| 데이터 | 출처 | 비고 |
|---|---|---|
| 기상 | 기상청 초단기실황 (공공데이터포털, `getUltraSrtNcst`) | 위경도 → 기상청 격자(nx, ny) 변환 필요. 강수량 `RN1`, 기온 `T1H`, 강수형태 `PTY` |
| 공연 | KOPIS 공연예술통합전산망 | 공연 목록(지역=광주) + 공연시설 상세의 위경도. 관객 수는 없으므로 공연장 좌석 수로 `crowd`를 정한다 |

- API 키는 `be/.env`에 넣고 `config.py`에서 읽는다 (카카오 키와 같은 방식).
- 응답을 그대로 쓰지 않고 2단계 `Weather`, `Event`로 바꾼다. 실패하면 "맑음, 공연 없음"으로 보고 경고만 띄운다.
- 같은 요청이 계속 오므로 10분 정도 캐시한다.

## 검증 기준

| 확인 | 기대 결과 |
|---|---|
| 배수가 모두 1인 시나리오 | 1단계 결과와 경로·비용이 같다 |
| 무작위 200쌍 × 각 시나리오 | A\* 비용 = 다익스트라 비용, A\* 방문 ≤ 다익스트라 방문 |
| 공연 시나리오 | 회피 경로가 공연장 반경 안을 덜 지나고, 상황 반영 시간이 평소 경로보다 짧거나 같다 |
| 공연 시간 창 밖 출발 | 평소 경로와 같다 |
| 맑음 → 비(전체 감속만) | 경로는 같고 시간만 늘어난다 |
| 통제 시나리오 | 통제 간선을 절대 지나지 않는다. 고립되면 경로 없음 |

- 1~4단계는 `python conditions.py`, `python search.py`로 터미널에서 먼저 확인한 뒤 API·화면에 붙인다.

## 예외 상황

| 상황 | 처리 |
|---|---|
| 출발/도착이 공연장 반경 안 | 피할 수 없으므로 그대로 탐색 (배수만 붙는다) |
| 출발/도착 바로 옆 간선이 통제 | 경로 없음, 화면에 이유 표시 |
| 시나리오 없음 | 기존 LEVEL 4 동작 |
| 외부 API 실패 (7단계) | 맑음·공연 없음으로 처리 + 경고 |
