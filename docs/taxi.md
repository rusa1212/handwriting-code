# 택시 모드 작업 계획

> 목표: 경로 추천 탭에 **[택시 모드]** 를 추가한다. 출발지·목적지가 정해지면 바로 경로를 찾고, 경로마다 **예상 택시비**를 보여 준다.
> 택시비는 카카오가 주는 값(`summary.fare.taxi`)을 그대로 쓰지 않고 **요금 규칙을 직접 구현해 계산**한 뒤, 카카오 값과 비교해 검증한다. (`mapping.md` 8장: 직접 이해하는 것이 목표)

## 진행 현황

| 단계 | 내용 | 구분 | 상태 |
|---|---|---|---|
| 1 | 카카오 응답에서 택시 계산 재료 꺼내기 (도로 구간별 거리·시간, `fare.taxi`) | 필수 | ✅ |
| 2 | 택시 요금 계산 모듈 (`be/taxi.py`): 기본·거리·시간 병산 요금 | 필수 | ⬜ |
| 3 | 할증 (심야, 시계외) + 출발 시각 | 필수 | ⬜ |
| 4 | 터미널 검증: 손으로 계산한 예제 + 카카오 `fare.taxi`와 오차 비교 | 필수 | ⬜ |
| 5 | 백엔드 API `POST /api/taxi` | 필수 | ⬜ |
| 6 | 화면: 모드 토글, 자동 검색, 요금 카드·요금 내역 | 필수 | ⬜ |
| 7 | 택시 경로 추천 (가장 싼 / 가장 빠른 / 균형) + 추천 이유 | 필수 | ⬜ |
| 8 | 출발 시각 지정 (미래 운행 정보 API), 지역별 요금표 | 선택 | ⬜ |

2~4단계는 **웹 없이 터미널에서** 끝낸다. 요금 계산이 틀렸을 때 원인이 화면인지 계산인지 헷갈리지 않도록 한다. (`webpagePlan.md` 9장과 같은 방식)

| 질문 | 결정 | 이유 |
|---|---|---|

| 요금표 | **서울 기준 하나**로 시작, 지역별은 8단계 | 먼저 한 지역 규칙을 정확히 맞추는 것이 중요하다 |

## 핵심 아이디어

택시 미터기는 **거리·시간 병산제**다. 빠르게 달릴 때는 거리로, 막혀서 느릴 때는 시간으로 요금이 오른다.

```text
택시비 = (기본요금 + 거리·시간 병산 요금) × 할증 배수     → 100원 단위
총 비용 = 택시비 + 통행료
```

- 카카오 응답의 `summary`에는 경로 전체의 거리·시간만 있다. 그런데 병산은 **구간마다 빠른지 느린지**에 따라 달라지므로 `sections[].roads[]`(도로 구간별 `distance`, `duration`, `traffic_speed`)를 써야 한다.
- 구간 속도가 기준(서울 15.72km/h) **이하**이면 그 구간은 시간 요금, **초과**이면 거리 요금으로 센다.
- 요금 계산은 경로 탐색과 무관한 **순수 함수**로 만든다: `taxi_fare(segments, depart_at, table) → FareBreakdown`. 그래야 터미널에서 숫자만 넣어 검증할 수 있다.

### 요금표 (초안, 서울 2023-02 개편 기준)

> ⚠ 구현 전에 서울시 공식 공지로 숫자를 다시 확인한다. 요금표는 코드 상수 한 곳(`TAXI_TABLES["seoul"]`)에만 둔다.

| 항목 | 값 |
|---|---|
| 기본요금 | 4,800원 (1.6km까지) |
| 거리요금 | 131m당 100원 |
| 시간요금 | 30초당 100원 (시속 15.72km 이하일 때) |
| 심야할증 | 22~23시, 02~04시 **20%** / 23~02시 **40%** |
| 시계외 할증 | 20% (서울 밖으로 나갈 때) |

## 1단계 ✅ 택시 계산 재료 꺼내기 (`map_api.py`, `schemas.py`)

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 1-1 | `Segment(distance, duration)` 스키마 + `_to_segments(sections)`: `roads[]`마다 거리(m)·시간(초) 추출 | ✅ 완료 |
| 1-2 | `get_routes()`에 `with_segments` 인자: 택시 모드에서만 구간 목록을 담는다 (자가용 응답 크기는 그대로) | ✅ 완료 |
| 1-3 | `Route`에 `kakao_taxi: int | None` 추가 (`summary.fare.taxi`, 검증·비교용) | ✅ 완료 |
| 1-4 | 확인: 구간 거리 합 = `summary.distance`, 구간 시간 합 ≈ `summary.duration` | ✅ 완료 |

- `roads[].duration`이 0인 구간(길이가 아주 짧은 구간)은 속도를 계산할 수 없으므로 거리 요금으로 센다.
- 응답을 한 번 파일로 저장해 두고(`be/data/sample_directions.json`) 2~4단계에서 API를 다시 부르지 않고 쓴다. (키 사용량 절약, 결과 재현)
- 구현:
  - `get_routes()`를 `fetch_directions()`(API 호출, 원본 JSON) + `parse_routes(data, with_segments)`(파싱)로 나눴다. 저장한 응답을 API 없이 파싱하기 위해서다. `get_routes()`는 둘을 이어 부르므로 `/api/routes` 동작은 같다.
  - `Route.segments`는 `Field(exclude=True)`라 서버 안에서만 쓰고 응답 JSON에는 나가지 않는다. `kakao_taxi`는 응답에 나간다 (화면은 아직 쓰지 않음).
  - `python taxi_sample.py`: 샘플 4개를 저장(없을 때만, `--refresh`로 다시 받기)하고 구간 합을 `assert`로 확인한다.
- `python taxi_sample.py` 결과 (2026-11-04 응답):

| 샘플 | 구간 | 거리 (구간 합 차이) | 시간 (구간 합 차이) | 통행료 | 카카오 택시비 |
|---|---|---|---|---|---|
| 구미역→금오산 | 7 | 3,823m (0) | 590초 (0) | 0원 | 8,000원 |
| 전남대→광주송정역 | 11 | 14,259m (0) | 1,216초 (0) | 0원 | 17,400원 |
| 서울역→강남역 | 13 | 10,644m (0) | 1,421초 (0) | 0원 | 17,700원 |
| 서울역→인천공항 | 32 | 59,133m (0) | 2,990초 (−22) | 3,200원 | 69,200원 |

- 알게 된 것:
  - 거리는 구간 합이 정확히 같다. 시간은 긴 경로에서 22초(0.7%) 차이가 났다. 카카오가 구간 시간을 따로 반올림하는 것으로 보인다 → 요금 계산은 구간 값을 쓰므로 영향 없음.
  - **`roads[]`는 생각보다 거칠다** (경로 하나에 7~32개). 구간 안의 짧은 정체는 평균 속도에 묻힌다. 느린 구간(15.72km/h 이하)은 샘플마다 1~4개, 시간으로 25~210초뿐이다 → 시간 요금 비중이 작게 나올 가능성이 있다. 4단계에서 카카오 값과 비교해 확인한다.
  - 네 샘플 모두 `alternatives=true`인데 **경로가 1개만** 왔다. 7-3(후보 경로 늘리기)이 꼭 필요하다.
  - 지역마다 요금표가 다르므로(구미·광주는 서울과 다름) 4단계 비교는 서울 샘플 2개를 기준으로 본다.

## 2단계 ⬜ 요금 계산 모듈 (`be/taxi.py`)

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 2-1 | `FareTable`(NamedTuple) + `TAXI_TABLES = {"seoul": ...}` 상수 | ⬜ |
| 2-2 | 구간 분류: `is_slow(seg, table)` → 시간 요금 / 거리 요금 | ⬜ |
| 2-3 | 병산 미터기: 기본거리를 먼저 소진한 뒤 거리·시간 단위마다 100원씩 올린다 | ⬜ |
| 2-4 | `FareBreakdown(base, distance_fare, time_fare, surcharge, total)`: 화면에 내역을 보여 주기 위해 합계만이 아니라 항목별로 돌려준다 | ⬜ |

- **미터기 흉내 내기:** 실제 미터기처럼 "남은 131m", "남은 30초" 카운터를 두고 구간을 차례로 흘려보낸다. 단순히 `총거리 ÷ 131m`로 나누면 느린 구간이 섞인 경로에서 값이 달라진다.
- 기본거리(1.6km)를 다 쓰기 전에는 거리·시간 요금이 붙지 않는다고 가정한다. 실제 미터기는 기본거리 안에서도 느리게 달린 시간이 기본거리를 깎는데, 이 차이는 4단계 오차를 보고 반영할지 정한다.
- 금액은 정수(원)로만 다룬다. 할증 배수를 곱한 뒤 **100원 단위 반올림**은 맨 마지막에 한 번만 한다.

## 3단계 ⬜ 할증 + 출발 시각

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 3-1 | `night_rate(depart_at)`: 출발 시각 → 1.0 / 1.2 / 1.4 | ⬜ |
| 3-2 | 시계외 할증: 목적지가 서울 경계 밖이면 1.2 (경계는 처음엔 사각형 bbox로 대략 판단) | ⬜ |
| 3-3 | 배수 합치기: 심야와 시계외가 겹칠 때 규칙 확인 후 반영 (더하기 vs 곱하기) | ⬜ |

- 출발 시각 하나로 할증을 정한다. 운행 중 23시를 넘기는 경우(예: 22:50 출발, 30분 운행)는 처음엔 무시하고 문서에 한계로 적는다. (`conditionRoutingPlan.md`의 "출발 시각 하나로 상황 고정"과 같은 결정)
- `depart_at`은 기본값을 지금 시각으로 둔다. 서버 시간대가 아니라 **한국 시간(`Asia/Seoul`)** 으로 판단한다.

## 4단계 ⬜ 터미널 검증 (`python taxi.py`)

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 4-1 | 손 계산 예제: 기본거리 이내, 모두 빠른 구간, 모두 느린 구간, 섞인 구간, 심야 23시 | ⬜ |
| 4-2 | 저장한 카카오 응답 여러 개로 `직접 계산` vs `fare.taxi` 오차 표 출력 | ⬜ |
| 4-3 | 오차가 큰 경우 원인 정리 (구간 속도 판단, 기본거리 처리, 할증 포함 여부) | ⬜ |

- 4-1은 `assert`로 고정해 나중에 코드를 고쳐도 깨지지 않는지 확인한다.
- 4-2 목표: 낮 시간 경로에서 **오차 ±5% 이내**. 카카오 `fare.taxi`가 할증·통행료를 포함하는지도 이 단계에서 확인해 문서에 적는다.

## 5단계 ⬜ 백엔드 API (`main.py`)

| 엔드포인트 | 요청 | 응답 |
|---|---|---|
| `POST /api/taxi` | `{ origin, destination, depart_at? }` | `[{ id, distance, duration, toll, path, fare: { base, distance_fare, time_fare, surcharge, total }, kakao_taxi }]` |

- 내부적으로 `get_routes(..., with_segments=True)` → 경로마다 `taxi_fare()`. 구간 목록은 응답에 넣지 않는다 (화면에 필요 없고 크다).
- 카카오 오류는 기존과 같이 502로 돌려준다.

## 6단계 ⬜ 화면 (`RecommendPage.jsx` 외)

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 6-1 | 모드 토글 (자가용 / 택시): `mode` 상태, 모드를 바꾸면 결과 초기화 | ⬜ |
| 6-2 | 택시 모드 자동 검색: 출발·도착이 둘 다 정해지면 `/api/taxi` 호출 (기존 `searchIdRef`로 늦은 응답 버리기) | ⬜ |
| 6-3 | `RouteCard`: 택시 모드에서 예상 택시비를 크게, 통행료·합계를 작게 | ⬜ |
| 6-4 | `FareDetail` 컴포넌트: 선택한 경로의 요금 내역 (기본 / 거리 / 시간 / 할증) + 카카오 예상 요금 비교 | ⬜ |
| 6-5 | `client.js`에 `getTaxiRoutes()`, `format.js`에 `formatWon()` | ⬜ |

- 자동 검색은 장소를 바꿀 때마다 요청이 가므로, 출발·도착을 연달아 바꾸는 경우에 대비해 300ms debounce를 건다 (선호도 슬라이더와 같은 방식).

## 7단계 ⬜ 택시 경로 추천

| 세그먼트 | 내용 | 상태 |
|---|---|---|
| 7-1 | `scoring.py` 일반화: 점수 요소를 `FACTORS` 표에서 고르게 바꿔 `fare`(택시비+통행료), `time`을 쓸 수 있게 | ⬜ |
| 7-2 | 슬라이더 2개(요금 / 시간) + 추천 이유: "2위 B보다 1,200원 싸고 3분 느립니다" | ⬜ |
| 7-3 | 후보 경로 늘리기: `priority=TIME`, `DISTANCE`로도 호출해 합치고 같은 경로 제거 (경로가 1개면 비교할 수 없음) | ⬜ |

- 7-3은 자가용 모드에도 그대로 도움이 된다.

## 8단계 ⬜ (선택) 확장

- 출발 시각 지정: 카카오 미래 운행 정보 API(`/v1/future/directions`, `departure_time`)로 "내일 23시 출발" 요금과 시간을 본다. 3단계 심야할증과 바로 연결된다.
- 지역별 요금표: `TAXI_TABLES`에 광주 등 추가, 출발지 좌표로 지역 결정.
- 모범·대형 택시 요금표 추가.

## 한계 (문서에 남겨 둘 것)

- 예상 요금이다. 실제 요금은 신호 대기, 기사 경로 선택, 실시간 교통에 따라 달라진다.
- 구간 속도는 카카오가 계산한 예상값이라 실제 정체와 다를 수 있다.
- 출발 시각 하나로 할증을 정하므로 운행 중 할증 시간대가 바뀌는 경우는 반영하지 않는다.
